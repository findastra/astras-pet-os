# The farm lock, Part 5a: the Friendly Farmer adds one pet to a farm or takes one away (2026-10-21)

Astra, 2026-10-21: "All recommended on the six farm lock questions", then "Build Part 5a here: the farm lock with the
installer's own pets and the installer's part, as the proposal and my answers say." Card 058, Part 5a, from the proposal
`docs/farm-lock-20261021.md`.

- **The farm lock**, `farm-lock-20261021.json` (`scripts/farm-lock-20261021.mjs`). It lives in the farm's own folder,
  is never committed, and is listed in `.gitignore`. It says exactly which pets a farm runs:
  - where each one's entry came from, with a SHA-256 of it;
  - which pets need which, and which ones the owner chose;
  - what each still needs that the Farmer cannot add (a core part, a third-party program, another computer).
- **The Friendly Farmer's farm-pets tool** (`scripts/farm-pets-20261021.mjs`, `the-farm-v1.0-farm-pets-v1.0`, a tool node
  on the System Map) has `plan add`, `add --yes`, `plan remove`, `remove --yes`, `check` and `lock`.
  - A pet brings every pet it requires.
  - A pet that others on the farm require stays unless `--with-dependents` is given.
  - A pet that came only as a need goes with `--and-unneeded`.
  - A running Startup Star restarts.
  - On a hub copy it only checks and records.
  - On Linux: `astras-pet-os pets ...`.
- **The installer** and the Linux setup tick the pets a picked pet needs (greyed, "Needed by ..."). The installer keeps
  the release's list of pets in `farm-catalog\`, writes the first farm lock, and opens with the farm's pets when run
  again. Its PowerShell twin is tested to give the same needs, hashes and lock as Node.
