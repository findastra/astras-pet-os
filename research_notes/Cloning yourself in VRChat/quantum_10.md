## 1. Signing up for IBM's free Open Plan, how QPU time is counted, how long small jobs take, and the Qiskit Runtime basics

### Takeaway
The free Open Plan gives **10 minutes of QPU time per rolling 28-day window**. As of November 2026 IBM counts this in "resource units", where 1 RU = 1 QPU minute. Open Plan instances exist only in IBM's **us-east** region, and session mode is not allowed on them. A job is billed for the time the QPU is "locked" for it. IBM's rule of thumb is **about 2 s of overhead plus 0.35 ms per shot per circuit**. So a 2-qubit, 4,000-shot job costs about **3.4 s**, and a 156-qubit, 10,000-shot random-bit job costs about **5.5 s**. Ten minutes is far more than a beginner's monthly experiments need, as long as she avoids heavy error-mitigation settings.

**How QPU time is counted**
- "Usage ... is determined by the amount of time a QPU is locked to execute workloads." A single job is billed for the time the QPU is locked for it, and a batch for the cumulative locked time of its jobs. A session is billed for its whole elapsed time, which is one more reason it is off-limits on the free plan **(read)** — [estimate-job-run-time.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/estimate-job-run-time.ipynb) (public page: [Workload usage](https://quantum.cloud.ibm.com/docs/en/guides/estimate-job-run-time)).
- **Failed jobs:** a job that fails "because of a system error" is billed zero. A job that fails because of user error, or that the user cancels, is billed for what it used "up to that point, including the overhead incurred to prepare the QPU" **(read)** — same file.
- **IBM's estimate formula:** `<per sub-job overhead> + (rep_delay + <circuit length>) * <num executions>`. The overhead is "approximately 2s per sub-job". `rep_delay` defaults to "250 microseconds on most IBM Quantum backends". "A typical circuit length is likely between 50-100 microseconds", and "A measurement ... can take 56 times longer than an `x` gate". `num executions` is circuits × shots. "If you aren't using any advanced error mitigation techniques or custom `rep_delay`, you can use `2+0.00035*<num executions>` as a quick formula." Error mitigation adds circuits, and PEA and PEC add "much higher overhead" **(read)** — same file.
- **Checking usage:** `job.usage()` (qiskit-ibm-runtime ≥ 0.30), `batch.usage()`, or `job.metrics()['usage']['quantum_seconds']`. The Instances page shows "real-time usage for the last 28 days (rolling)" **(read)** — [estimate-job-run-time.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/estimate-job-run-time.ipynb); [max-execution-time.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/max-execution-time.ipynb).
- **Safety cap:** `options.max_execution_time` (in seconds) caps a job by "QPU usage (quantum usage only), not wall clock time". The service-wide maximum is three hours **(read)** — [max-execution-time.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/max-execution-time.ipynb). "A job's QPU consumption ... scales with the number of shots", and heavier error-suppression settings "can cause your jobs to run longer" **(read)** — [minimize-time.mdx](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/minimize-time.mdx).

**Qiskit Runtime basics needed to submit a job**
- There are two primitives. **Sampler** returns measured bitstrings and counts. **Estimator** returns expectation values of observables. The IBM versions add error mitigation "as a cloud-based service", while `StatevectorSampler` and `StatevectorEstimator` run locally for free **(read)** — [primitives.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/primitives.ipynb).
- **The API changed in 2026:** IBM's hello-world now imports "Client-side primitive introduced in qiskit-ibm-runtime 0.50.0" (`from qiskit_ibm_runtime.executor_estimator import Estimator`) and marks the old `from qiskit_ibm_runtime import Estimator` as "Legacy server-side primitive". Many tutorials still use `SamplerV2` and `EstimatorV2`, so older code still appears in the docs **(read)** — [hello-world.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/hello-world.ipynb); [max-execution-time.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/max-execution-time.ipynb); [grovers-algorithm.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/grovers-algorithm.ipynb).
- **The minimal job (IBM Learning lesson):** `service = QiskitRuntimeService()`, then `backend = service.least_busy(operational=True)`, then transpile with `generate_preset_pass_manager(backend=backend, optimization_level=1)` into an "ISA" circuit, then `Sampler(mode=backend).run([isa_qc], shots=1024)`, then `result[0].data.<register>.get_counts()` **(read)** — [Bits, gates and circuits lesson](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/utility-scale-quantum-computing/bits-gates-and-circuits.ipynb).
- Inputs are packaged as **PUBs** ("primitive unified blocs"). For the Estimator a PUB is `(circuit, observables, parameter_values, precision)`, so a whole parameter sweep, such as 21 angles, goes in one job **(read)** — [chsh-inequality.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/chsh-inequality.ipynb); [execution-modes.mdx](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/execution-modes.mdx).
- **Free rehearsal:** fake backends (`qiskit_ibm_runtime.fake_provider`, e.g. `FakeBelemV2`) and `AerSimulator.from_backend(backend)` (a noisy copy of a real QPU) run the same code locally **(read)** — [hello-world.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/hello-world.ipynb); [chsh-inequality.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/chsh-inequality.ipynb).

### Inferences
- **Typical job sizes (my arithmetic, using IBM's quick formula `2 + 0.00035 × circuits × shots` seconds):**
  - A 2-5 qubit circuit with 1,000 shots costs about 2.4 s, and with 4,000 shots about 3.4 s.
  - A 21-point parameter sweep at 1,000 shots costs about 9.3 s.
  - A **156-qubit Hadamard random-bit job with 10,000 shots** costs about 5.5 s and gives 1.56 million raw bits. The cost depends on shots and circuits, not on qubit count, because all the qubits are measured in parallel within each shot.
  - Ten minutes is 600 s, or about 175 Bell-pair jobs of 4,000 shots each.
- The 2 s per-job overhead dominates small jobs. Batching many small circuits into **one** job, as several PUBs or a parameter sweep, saves more QPU time than cutting shots does.
- IBM's tutorial estimates (2 min for CHSH, 105 s for Ising) are far above the lean formula because they use Estimator error mitigation and many parameter points. For the free plan, the cheap path is the Sampler with default settings, a `max_execution_time` on every job, and a full rehearsal on a fake backend first. Bugs found on hardware still cost time ("user error" is billed).
- Since dry-run is not on the Open Plan, her best cost check before a job is the formula plus `job.usage()` after small test jobs.
- The API key must never go into either repo, which matches the PetOS privacy rules. Store it with `save_account()` on her own PC only.

## 2. Other free or cheap access an individual can use (status 2026), and free simulators

### Takeaway
Beyond IBM, the realistic free hardware routes for an individual are **Quantum Inspire** (QuTech, free registration, Tuna-5/9/17 superconducting chips), **Open Quantum via qBraid** ($50 of credit every 90 days on IonQ, Rigetti, IQM and AQT) and **Qollab** (monthly credits on IonQ Forte). For learning and for building VR visualizations, her own PC is the strongest free tool: Qiskit Aer, fake IBM backends, and about **31 qubits** of exact simulation on a 24 GB gaming GPU.

## 4. Designing the Quantum 10: candidate experiments for 10 free minutes a month

### Takeaway
Twelve beginner experiments fit comfortably. Run lean (Sampler, default settings, about 1,000-4,000 shots, batched sweeps), **all twelve together cost about 2.5 minutes of QPU time** by IBM's formula, leaving room for re-runs. Each has been run on IBM hardware before, either in IBM's own tutorials and lessons or in published papers. The ones that would not fit are the heavy versions: IBM's error-mitigated tutorials of 4-70 minutes, and the 120-qubit GHZ record. The face-on-the-Bloch-sphere art piece is new: no prior example of face data on qubits was found.

### Cited Findings (sources per experiment)
- **Euler slider (H, P(θ), H):** a classroom paper ran exactly this "phase gate between two Hadamards" Mach-Zehnder circuit on an IBM device at several phases, and the outcome probabilities follow cos²(φ/2) and sin²(φ/2) **(search summary)** — [arXiv 1805.06275](https://arxiv.org/pdf/1805.06275). A biased Mach-Zehnder interferometer was run on IBM's Armonk chip with tomography between the phase shifter and the second beam splitter **(search summary)** — [arXiv 2203.17062](https://arxiv.org/pdf/2203.17062). The algebra (amplitude of 0 = (1 + e^(iθ))/2, which is 0 at θ = π) is in the earlier report — [report](../../reports/Face%20tracking%20avatars%20and%20quantum%20simulation.md).
- **Bell/CHSH:** IBM's tutorial builds "a parameterized Bell circuit", sweeps 21 phases from 0 to 2π, and plots two CHSH witnesses against the classical bound ±2 and the Tsirelson bound ±2√2. It selects a QPU with at least 127 qubits, uses the Estimator, and estimates **2 minutes on Heron r3** **(read)** — [chsh-inequality.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/chsh-inequality.ipynb). IBM Learning also has a "CHSH game" lesson **(read)** — [chsh-game.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/basics-of-quantum-information/entanglement-in-action/chsh-game.ipynb). Device-independent QRNGs based on Bell tests have been built on IBM machines **(sibling note, search summary)** — [arXiv 2309.05299](https://ar5iv.labs.arxiv.org/html/2309.05299).
- **Quantum coin (random bits):** Hadamard-and-measure QRNGs were run on IBM's 20-qubit devices. Raw output was "biased and correlated" (a 43,560-bit sample on IBM Q 20 Tokyo) and was tested with NIST SP 800-22 **(search summary)** — [arXiv 1906.04410](https://arxiv.org/pdf/1906.04410); [IACR ePrint 2020/078](https://eprint.iacr.org/2020/078). Temporal correlation was traced to qubit reset **(search summary)** — [arXiv 2004.01330](https://arxiv.org/abs/2004.01330v1). The full design is in `randomness_and_moods.md`.
- **GHZ "cat" state:** IBM Learning's "Bits, gates and circuits" lesson builds a GHZ state, (|000⟩ + |111⟩)/√2, and runs entanglement on a real device (`ibm_kingston` in its example) **(read)** — [bits-gates-and-circuits.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/utility-scale-quantum-computing/bits-gates-and-circuits.ipynb). Shadow tomography of a GHZ state takes **under 10 s on Heron r2** **(read)** — [shadow-tomography.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/shadow-tomography.ipynb). The record is **120 qubits, fidelity 0.56(3)**, on `ibm_aachen`, with 8 parity-check qubits and 28% post-selection; fidelity above 0.5 certifies genuine entanglement across all the qubits **(search summary)** — [arXiv 2510.09520 "Big cats"](https://arxiv.org/pdf/2510.09520); [Quantum Computing Report](https://quantumcomputingreport.com/ibm-reports-largest-entangled-state-to-date-achieving-0-56-fidelity-on-120-superconducting-qubits/).
- **Teleportation:** the IBM Learning lesson "Quantum teleportation and superdense coding" (Kifumi Numata, 26 April 2024) has a section, "Teleportation on a real quantum computer", that uses dynamic circuits (mid-circuit measurement and feed-forward), with 1,000 or 10,000 shots in its simulator runs **(read)** — [teleportation.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/utility-scale-quantum-computing/teleportation.ipynb).
- **Grover on 2 qubits:** the IBM Learning lesson marks |01⟩, runs 1,024 shots, and has an "Experiment with Real Devices" section **(read)** — [grovers-algorithm lesson](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/utility-scale-quantum-computing/grovers-algorithm.ipynb). IBM's tutorial version is "under one minute on an Eagle r3" with 10,000 shots **(read)** — [grovers-algorithm.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/grovers-algorithm.ipynb).
- **Deutsch-Jozsa:** a 4-qubit implementation ran on IBMQ Manila with 8,000 shots **(search summary)** — [arXiv 2109.07910](https://arxiv.org/pdf/2109.07910). An entanglement-based variant ran on IBM's 5-qubit machine **(search summary)** — [arXiv 1708.06375](https://arxiv.org/pdf/1708.06375). Another run was on ibmqx4 **(search summary)** — [leftasexercise blog](https://leftasexercise.com/2019/02/18/searching-for-balance-running-the-deutsch-jozsa-algorithm-on-ibms-q-experience/). IBM Learning teaches the theory **(read, course table of contents)** — [Fundamentals of quantum algorithms](https://raw.githubusercontent.com/Qiskit/documentation/main/learning/courses/fundamentals-of-quantum-algorithms/_toc.json).
- **How long a qubit remembers (T1/T2):** IBM defines T1 as "the average duration a qubit remains in its excited state |1⟩ before decaying", and T2 as the time over which a qubit "maintains phase coherence of a superposition". Both are published per qubit, readable with `backend.properties().t1(q)` and `.t2(q)` **(read)** — [qpu-information.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/qpu-information.ipynb). Qiskit Experiments ships `T1`, `T2Ramsey` and `T2Hahn` experiments; a T1 run fixes a delay and a number of shots, sweeps the delay, and fits an exponential. Its manual demonstrates this on a fake backend **(read)** — [t1.rst](https://raw.githubusercontent.com/qiskit-community/qiskit-experiments/main/docs/manuals/characterization/t1.rst); [t2ramsey.rst](https://raw.githubusercontent.com/qiskit-community/qiskit-experiments/main/docs/manuals/characterization/t2ramsey.rst); [t2hahn.rst](https://raw.githubusercontent.com/qiskit-community/qiskit-experiments/main/docs/manuals/characterization/t2hahn.rst).
- **Tiny toy universe (Ising):** IBM's "Simulate time evolution of the transverse-field Ising model" estimates **105 s on Nighthawk r2** **(read)** — [time-evolution.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/time-evolution.ipynb). The Q-CTRL version (2 min) and the TEM kicked-Ising version use Qiskit Functions, which IBM lists as Premium functionality **(read)** — [transverse-field-ising-model.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/transverse-field-ising-model.ipynb); [plans-overview.mdx](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/guides/plans-overview.mdx).
- **Tiny toy universe (Schwinger model, "matter from nothing"):** a reduced (3+1)D Schwinger pair-production model ran on a 5-qubit IBM device, and its production rate agreed with the Schwinger-effect prediction within uncertainties **(search summary)** — [arXiv 2112.06863](https://ar5iv.arxiv.org/html/2112.06863). The four-qubit pair-creation precedent ran on trapped ions **(search summary)** — [arXiv 1605.04570](https://arxiv.org/pdf/1605.04570). The large-scale version used 112 IBM qubits **(earlier notes)** — [arXiv 2401.08044](https://arxiv.org/pdf/2401.08044). IBM's non-Abelian hadron-dynamics tutorial takes 6 min on Heron **(read)** — [loop-string-hadron-dynamics.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/loop-string-hadron-dynamics.ipynb).
- **Art: face on the Bloch sphere:** QuantumBlur is "a tool for doing quantum things with height maps and images", with Qiskit or the minimal MicroMoth SDK; there is an explainer blog and paper **(read)** — [QuantumBlur README](https://raw.githubusercontent.com/qiskit-community/QuantumBlur/main/README.md); [arXiv 2007.11510](https://arxiv.org/abs/2007.11510). Its encoding uses n = log2(W) + log2(H) qubits for a W×H image and can be run "through emulation ... or running it on quantum hardware" **(search summary)** — [arXiv 2112.01646](https://ar5iv.labs.arxiv.org/html/2112.01646). The single-qubit state cos(θ/2)|0⟩ + e^(iφ) sin(θ/2)|1⟩ is the Bloch-sphere point (θ, φ) **(earlier report)** — [arXiv 2503.19109](https://arxiv.org/pdf/2503.19109).
- **Bonus candidates:** factoring 15 with Shor's algorithm, **3 s on Eagle r3** **(read)** — [shors-algorithm.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/shors-algorithm.ipynb); repetition code ("fix a flipped bit"), **under 10 s on Heron** with 1,000 shots **(read)** — [repetition-codes.ipynb](https://raw.githubusercontent.com/Qiskit/documentation/main/docs/tutorials/repetition-codes.ipynb).

### Inferences
- **Monthly budget (my arithmetic):** items 1-12 in their lean versions total about **126 s plus about 27 s for T1/T2 ≈ 2.5 minutes**, a quarter of the free window. The rest covers retries, higher shot counts (4,000 instead of 1,000) and one of IBM's full tutorials, such as CHSH at about 2 min.
- **Picking "the Quantum 10" from the 12:** my suggested final ten are 1, 2, 3, 4, 5, 6, 8, 9, 10 and 11. They carry her three threads: Euler (1), AI Astra's quantum coin (2, 3) and toy universes (9, 10). Item 11 is the bridge to Astralese, and the core skills come from 4, 5, 6 and 8. Items 7 and 12 (and the repetition code) are good swaps for a second month.
- **What CHSH does and does not prove:** on a cloud chip both qubits sit on one processor, with no distance between them and no independent setting choices. A CHSH value above 2 shows the correlations are quantum, but it does not *certify* the coin's randomness against a cheating device. Certified randomness so far needed Quantinuum's H2 and supercomputer verification (sibling note). So the honest wording is that the coin comes from the same kind of qubits that just beat the classical limit.
- **Euler slider detail:** sweeping θ with a parameterized circuit in **one** job (21 points) costs about the same as 4 separate jobs, because of the 2 s overhead per job. Note: H·P(π)·H = X, so the θ = π point is a built-in check that the hardware flips 0 to 1.
- **Face constellation design:** one qubit per Unified Expressions weight w ∈ [0, 1], rotated with RY(π·w), puts w on the Bloch sphere's polar angle. A second shape, such as an eye or brow value, could set the phase φ with RZ. Reading back ⟨Z⟩ recovers w = arccos(⟨Z⟩)/π, and the hardware noise shows up as how far the read-back face drifts from the input: a natural art metric. Only numbers go to IBM, never video, and no recordings should be committed (PetOS privacy rules).
- **Workflow that keeps the free window safe:** build and verify every item on `AerSimulator.from_backend(...)` first, then submit it to hardware as one job with `max_execution_time` set (for example 60 s), and log `job.usage()` into a small results table for her README.

### Gaps

- I found no prior work encoding face-tracking data (or any facial expression) into qubits on IBM hardware, so item 11 appears novel; "no source found" does not mean nothing exists.
- I did not find a recent (Heron or Nighthawk era) published Deutsch-Jozsa run. The hardware sources are 2017-2021 devices.
- I could not verify which qubit counts a few-qubit Schwinger model needs on today's IBM heavy-hex or grid layouts without the papers' full text.
- I did not check whether IBM's Learning teleportation lesson reports a hardware fidelity number.
