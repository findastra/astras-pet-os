## Run once on the PC

When the PC is on, from a normal (not administrator) PowerShell window in the hub folder:

```
powershell -ExecutionPolicy Bypass -File scripts\cung-list-install-20261026.ps1 -DryRun
powershell -ExecutionPolicy Bypass -File scripts\cung-list-install-20261026.ps1
```

The first line only shows what it would do. Each step checks first and skips what is already there, so running it again
is safe. It ends with a table of every step.

| Step | What | How | Administrator? |
|---|---|---|---|
| 1 | Ollama | `winget install --id Ollama.Ollama --scope user` | No |
| 2 | Node.js LTS, only when `node` is missing | `winget install --id OpenJS.NodeJS.LTS` | Yes: Windows asks |
| 3 | uv, then a first download of Serena | `winget install --id astral-sh.uv`, then `uvx --from git+https://github.com/oraios/serena@9e1cced0c34ed48d668e179f7c56c77b4d14a3e3 serena --version` | No |
| 4 | Docker Desktop, only if she answers y | `winget install --id Docker.DockerDesktop --interactive` (its own installer window) | Yes: Windows asks |
| 5 | Gemini CLI | `npm install -g @google/gemini-cli` | No |
| 6 | Dyad | `winget install --id Dyad.Dyad --scope user`; if winget fails, the download page https://www.dyad.sh/ | No |
| 7 | ccusage, a test run only | `npx -y ccusage@latest daily --since <a week ago>` | No |

What the script never does: read, change or sign in with Astra's Claude account or its credentials; set an API key; add
anything to Startup apps (only Startup Star belongs there, AGENTS.md); run itself as administrator. Ollama's installer
adds itself to Startup apps on its own; the script says so, and she turns it off in Task Manager.

The winget package ids were checked against the winget catalog (microsoft/winget-pkgs) on 2026-10-26: `Ollama.Ollama`
(user install), `OpenJS.NodeJS.LTS` (installs for all users), `astral-sh.uv` (portable), `Docker.DockerDesktop` (all
users), `Dyad.Dyad` 1.19.0 (user install, Apache-2.0).

## Context7 and Serena in Claude Code (items 2 and 7)

`.mcp.json` in the hub's root is Claude Code's project file for MCP servers. The first time Claude Code opens the hub
folder it asks whether to use the two servers in it. Say yes to `context7`; `serena` changes how agents work
(below), so it is Astra's own yes. `claude mcp reset-project-choices` asks again.

- **context7** is Upstash's hosted server at `https://mcp.context7.com/mcp`. It works without a key at a lower rate
  limit. A free key raises the limit: it is a key request for API Fairy (`CONTEXT7_API_KEY`, Upstash, free;
  `skills/key-request`), and the key goes in a local server entry, never in `.mcp.json`:
  in PowerShell, `claude mcp add --scope local --transport http context7 https://mcp.context7.com/mcp --header "Authorization: Bearer $env:CONTEXT7_API_KEY"` (a local entry, stored in her own Claude Code settings on the PC).
- **serena** runs on Astra's PC through uv:
  `uvx --from git+https://github.com/oraios/serena@9e1cced0c34ed48d668e179f7c56c77b4d14a3e3 serena start-mcp-server --context ide --project <the hub> --agent-interface tools --open-web-dashboard false`.
  - **Pinned** to Serena commit `9e1cced0c34ed48d668e179f7c56c77b4d14a3e3` (the one tested below), not GitHub's newest: a new Serena only reaches the
    farm when someone tests it and changes this pin in a pull request Astra approves.
  - **`--context ide`, not `claude-code` (review fix, 2026-10-26).** Serena's `claude-code` context sends Claude a
    prompt that calls the built-in Read and Edit tools FORBIDDEN on code files and routes every code edit through
    Serena. That would quietly change how every agent in the hub works, which only Astra (L4) can approve. The `ide`
    context forbids nothing: its prompt only asks the agent to prefer Serena's symbol tools and avoid reading whole
    source files, and it leaves out Serena's own file and shell tools (`read_file`, `create_text_file`,
    `execute_shell_command`, `find_file`, `list_dir`), so Claude Code's own tools and permission prompts stay in charge.
  - **What turning it on still changes:** the agent gets Serena's editing tools (`replace_symbol_body`,
    `rename_symbol`, ...) and that "prefer Serena" hint. Claude Code asks before it starts any server from a project's
    `.mcp.json`, and nothing in the hub turns that question off, so Serena stays off until Astra says yes to it there.
  - `--agent-interface tools` gives Claude one tool per action (`find_symbol`, `replace_symbol_body`, ...). Without it,
    this Serena version starts with only two tools and a Python prompt.
  - `--project ${CLAUDE_PROJECT_DIR:-.}`: the hub folder Claude Code was opened in.
  - `.serena/project.yml` tells Serena to read JavaScript with the TypeScript language server. Its cache and
    `project.local.yml` stay out of git (Serena's own `.serena/.gitignore`), and so do its memories (the hub's
    `.gitignore`): what an agent writes there is notes, not source.

**Checked on 2026-10-26** (Linux build session, Serena 2.1.1.dev0 at commit `9e1cced0c34ed48d668e179f7c56c77b4d14a3e3`, uv 0.11.32): the exact command in
`.mcp.json` (`--context ide`, re-run after the review fix) started, answered the MCP `initialize` handshake, listed 23 tools,
its instructions contained no FORBIDDEN rule, and
`get_symbols_overview` on `scripts/animal-guard-20261013.mjs` returned its functions (`assertAnimal`, `assertInside`,
...). The Codex form below listed 24 tools and answered the same lookup. Context7 could not be reached from the build
session (its network blocks that address), so it is first tested on Astra's PC: run `/mcp` in Claude Code and look for
`context7` as connected.

## The same for Codex

Codex reads `%USERPROFILE%\.codex\config.toml` (a trusted project's own `.codex\config.toml` works too). Add these
lines; Serena finds the project from the folder Codex is started in:

```toml
[mcp_servers.context7]
url = "https://mcp.context7.com/mcp"
# Optional, after API Fairy has the key: bearer_token_env_var = "CONTEXT7_API_KEY"

[mcp_servers.serena]
command = "uvx"
args = ["--from", "git+https://github.com/oraios/serena@9e1cced0c34ed48d668e179f7c56c77b4d14a3e3", "serena", "start-mcp-server", "--context", "codex", "--project-from-cwd", "--agent-interface", "tools", "--open-web-dashboard", "false"]
startup_timeout_sec = 60
```
