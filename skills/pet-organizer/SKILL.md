# Pet organizer (Astra, 2026-10-16)

The numbered pet list on [findastra/findastra](https://github.com/findastra/findastra) is written by the Friendly
Farmer's profile round (`scripts/farmer-profile-20261009.mjs`, run daily by that repo's
`.github/workflows/farmer-profile-round.yml`) from **`pet-programs.json`** in this repo. **Fix the JSON or the
script, never only the README**: the next round puts the old text back.

## The line shape
```
N. **[Pet](https://github.com/findastra/repo)** -- what the pet does [status]
   - [`home-name`](its page) -- the pet program
   - [`tool`](https://github.com/findastra/tool) -- each tool
```
- **The pet line is the pet and what it does, nothing else** (Astra, 2026-10-16). The pet's name (`icon` in
  pet-programs.json) comes first and is its own link, to its repo. A private repo is not linked.
- **No name twice.** The repo is not listed again beneath the pet, and the home's name is said once, as its link
  text (`the-farm -- the pet program`, not `the-farm -- The Farm, the pet program`).
- **Home** is the first sub-bullet when `assigned` is true, linked to its page (`profile.tools.<repo>.home_url` in
  pets.json, else a live github.io site, else its page on The Farm, else the repo when they share a name). Unnamed:
  `` `pet-program-N` -- pet program, not named yet ``. Suggested homes live in `idea` until Astra approves one.
- **Tools** follow, from `profile.tools.<repo>.tools`. A repo that is more than the pet's own
  (`repo_note`, e.g. astras-pet-os, "Astra's PetOS home repo") keeps its own line before the tools, unless Astra
  links that repo above the numbered list: she moved astras-pet-os to its own line there on 2026-10-17, so it is not
  repeated under the Friendly Farmer.
- **Astra's own labels stay.** A line in another section may show a name that is not the repo's, as long as its link
  points at the repo (`` [`fuzzboi-factory`](https://github.com/findastra/fuzzbois) ``, Astra, 2026-10-17). The round
  keeps it and does not add the repo again. A line she writes with a dash in place of ` -- ` (` -— `) is kept word for
  word too.
- **What it does** is `mini_descriptor.text`: a finished sentence about what the pet does. It does not repeat the home,
  does not start with a category (`Tasks:`, `AI cost:`), and uses floors for counts ("30+ tools").
- **Status goes in [brackets] at the end**, never in the job. The round moves `Planned: …` to `[planned]` and
  `Not decided yet: …` to `[job not chosen yet]` by itself.
- **Private repos** are not linked: `` `repo` *(private)* ``.
- One pet per number. A repo that says it is "pet program (#N)" belongs in the numbered list, not in Web & More.
- The full rule list the GitHub Goldfish checks is in
  `findastra/github-goldfish/docs/profile-style-20261009.md` ("Pet roster").

## Steps
1. Read the profile README and list every line that breaks the shape above. Say which ones are right too.
2. Run the **pet-finder** trick (`skills/pet-finder`) so missing pets are fixed in the same pass.
3. Fix the source:
   - a pet's name, home or job → its entry in `pet-programs.json` (`icon`, `program` + `assigned`, `mini_descriptor.text`);
   - the line shape itself → `scripts/farmer-profile-20261009.mjs`, plus the Goldfish's `PET_LINE` and its style doc,
     so the two never disagree.
   Never invent a pet name or a home: a placeholder or a missing home goes to Astra as a list.
4. `npm run build` and `npm test` here.
5. Preview the profile: copy the findastra README to a temp file and run
   `node scripts/farmer-profile-20261009.mjs --readme <temp README> --registry pets.json --repos <repos.json>`
   (`repos.json` = `[{ "name", "private", "description" }]`, or leave `--repos` out to ask GitHub). Read every pet line.
6. Core rule: this repo changes on a branch and merges only with Astra's OK. The findastra README is regenerated by the
   next round, or pushed by hand with her OK once the script is merged.
7. Tell Astra what changed, what was already right, and what only she can decide (names, homes).
